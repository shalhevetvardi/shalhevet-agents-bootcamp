# Rebuild Plugin - אריזת הסוכן מחדש להתקנה מחדש

## מה זה עושה (במילים פשוטות)

כשמשנים משהו בסוכן - מסמך ידע, סקיל, או האופי שלו - משנים אותו ב**תיקיית המקור** (המקום שבו הקבצים האמיתיים של הסוכן גרים, בתוך הריפו). אבל הגרסה ש**מותקנת** ב-Claude עדיין לא מכירה את השינוי - היא צילום ישן.

**Rebuild = אריזה מחדש.** הסקיל אורז את תיקיית המקור המעודכנת לקובץ פלאגין אחד (`.plugin`), ושם אותו ב-`plugins-to-install/`. משם המשתמש **מתקין אותו מחדש דרך קלוד** - וההתקנה מחדש מעדכנת את הגרסה הקיימת.

> התהליך במשפט: **מתקנים את תיקיית המקור ← עושים rebuild ← הפלאגין נכנס ל-`plugins-to-install/` ← מתקינים מחדש בקלוד.**

## כלל בטיחות חשוב - איך מתקינים

ההתקנה נעשית **תמיד דרך הממשק של קלוד** (גרירת הקובץ, או הגדרות ← פלאגינים ← התקנה מקובץ). **הסקיל לא כותב בעצמו לקבצים הפנימיים של קלוד** (למשל `installed_plugins.json` / `marketplace.json`). כתיבה ישירה לקבצים האלה עלולה לשבור את טעינת הפלאגינים ולגרום לכל הסוכנים המותקנים להיעלם בשקט - לכן לא עושים את זה. אורזים בלבד; קלוד מתקין.

## מתי מפעילים

אחרי כל שינוי בסוכן. "שמרתי" זה לא "הסוכן המותקן יודע" - רק אחרי rebuild + התקנה מחדש.

## מערכת הפעלה - קרא לפני שאתה מריץ פקודה

הפקודות למטה שונות בין Mac, Windows ו-Linux. **בדוק את מערכת ההפעלה של המשתמש** - היא רשומה ב-`CLAUDE.md` של הריפו, בשדה "מע' הפעלה" (אם לא בטוח - שאל) - **ובחר את הפקודה המתאימה.**

## השלבים שאני מבצע

1. **מזהה את הסוכן/ים לארוז.** מחפש תיקיות סוכן ב-`agents/ready/` וב-`agents/in-progress/` (כל תת-תיקייה שיש בה `.claude-plugin/plugin.json`). אם יש כמה - שואל איזה. אם יש אחד - ממשיך איתו ומודיע. **אם המשתמש ביקש "את כל הסוכנים" / "לעדכן את כולם" - חוזר על התהליך לכל תיקיית סוכן בנפרד ומדווח רשימה.**

2. **מוודא מקור תקין.** בודק שיש `.claude-plugin/plugin.json`. אם אין - עוצר ומסביר, בלי לנחש.

3. **שתי בדיקות בטיחות לפני אריזה (מונעות "היעלמות שקטה"):**
   - **א. מבנה ה-SKILL.** קלוד מזהה סוכן רק אם קובץ ה-SKILL שלו יושב בנתיב `skills/<שם-הסוכן>/SKILL.md` בתוך הפלאגין. אם ה-SKILL.md יושב בשורש תיקיית הסוכן - הפלאגין יותקן אבל הסוכן **לא יופיע** ברשימה, בלי שום שגיאה. אם זה המצב - מעביר ל-`skills/<שם>/SKILL.md` (ואת מסמכי הידע ל-`skills/<שם>/references/`), מתקן נתיבים בגוף הקובץ, **בתיקיית המקור** (אחרת ה-rebuild הבא אורז מחדש את המבנה השבור).
   - **ב. BOM ב-plugin.json.** בודק שקובץ `plugin.json` לא מתחיל ב-BOM (שלושה בתים נסתרים שעורכי Windows מוסיפים לפעמים). BOM שובר את קריאת ה-JSON והפלאגין כולו לא נטען, בשקט. אם יש BOM - כותב את הקובץ מחדש ב-UTF-8 **בלי BOM**.

4. **מעלה את מספר הגרסה** ב-`plugin.json` (הספרה האחרונה, למשל מ-`0.1.0` ל-`0.1.1`). זה מה שגורם לקלוד לזהות שזו גרסה חדשה בהתקנה מחדש.

5. **מוודא שקיימת `plugins-to-install/`** בשורש ריפו הקורס - התיקייה שמכילה את `agents/` (אותה תיקייה שהשיחה מחוברת אליה). אם לא קיימת - יוצר אותה שם בעצמו.

6. **אורז** את תיקיית הסוכן לקובץ `.plugin` בתוך `plugins-to-install/`. **חשוב: הנתיבים בתוך הארכיון חייבים forward slashes (`/`), אחרת ההתקנה נשברת ב-Windows.**
   - **Mac / Linux:**
     ```bash
     cd <תיקיית-הסוכן>
     zip -r <שורש-הריפו>/plugins-to-install/<שם-הסוכן>.plugin . -x "*.DS_Store" -x "*/.git/*"
     ```
   - **Windows (PowerShell):** **אל תשתמש ב-`Compress-Archive`** - היא כותבת נתיבים עם backslash (`\`) ששוברים את ההתקנה. במקום זה, אריזה דרך `System.IO.Compression` עם forward slashes:
     ```powershell
     Add-Type -AssemblyName System.IO.Compression.FileSystem
     $src = "<תיקיית-הסוכן>"; $dest = "<שורש-הריפו>\plugins-to-install\<שם-הסוכן>.plugin"
     if (Test-Path $dest) { Remove-Item $dest }
     $zip = [System.IO.Compression.ZipFile]::Open($dest, 'Create')
     Get-ChildItem -Recurse -File $src | Where-Object { $_.FullName -notmatch '\\\.git\\|\.DS_Store$' } | ForEach-Object {
       $entry = $_.FullName.Substring($src.Length).TrimStart('\').Replace('\','/')
       [void][System.IO.Compression.ZipFileExtensions]::CreateEntryFromFile($zip, $_.FullName, $entry)
     }
     $zip.Dispose()
     ```

7. **מדווח למשתמש:** נתיב הקובץ, הגרסה החדשה, ומנחה אותו להתקנה מחדש (למטה).

## מה המשתמש עושה אחרי (אני מנחה אותו)

> "הפלאגין המעודכן מחכה ב-`plugins-to-install/<שם>.plugin`. עכשיו:
> 1. התקינו אותו מחדש בקלוד - גררו את הקובץ לחלון Claude Desktop, או: הגדרות ← פלאגינים ← התקנה מקובץ. **ההתקנה מחדש מעדכנת את הגרסה הקיימת - אין מה למחוק, ואין כפילות.** (אם בכל זאת מופיעות שתי גרסאות, הסירו את הישנה מהגדרות ← פלאגינים.)
> 2. סגרו את קלוד לגמרי ופתחו מחדש.
> 3. פתחו שיחה חדשה, ובדקו שהסוכן **מופיע ברשימה** ומכיר את השינוי."

## כללים

- **לא כותב לקבצים הפנימיים של קלוד.** ההתקנה היא דרך הממשק בלבד. הסקיל אורז ומעתיק - לא נוגע ב-`installed_plugins.json` / `marketplace.json`.
- **מקור אחד.** מתקנים תמיד בתיקיית המקור (`agents/ready/<שם>/` או `agents/in-progress/<שם>/`), לעולם לא בגרסה המותקנת.
- **בדיקות הבטיחות (שלב 3) הן חלק מהתהליך, לא אופציה** - הן מונעות היעלמות שקטה של סוכנים.
- **forward slashes בארכיון** - תמיד, במיוחד ב-Windows.
- **פקודות מותאמות למערכת ההפעלה** (Mac / Windows / Linux), לפי שדה "מע' הפעלה" ב-`CLAUDE.md`.
- **לא ממציא נתיבים.** לא מצא תיקיית סוכן / `plugin.json` - עוצר ושואל.
- שפה למשתמש: עברית פשוטה. נתיבים ושמות קבצים: אנגלית.
