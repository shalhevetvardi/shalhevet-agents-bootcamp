# Rebuild Plugin - אריזת הסוכן מחדש והחלפת הגרסה המותקנת

## מה זה עושה (במילים פשוטות)

כשמשנים משהו בסוכן - מסמך ידע, סקיל, או האופי שלו - משנים אותו ב**תיקיית המקור** (המקום שבו הקבצים האמיתיים של הסוכן גרים, בתוך הריפו). אבל הגרסה ש**מותקנת** ב-Claude עדיין לא מכירה את השינוי - היא צילום ישן.

**Rebuild = אריזה מחדש + התקנה מחדש.** הסקיל אורז את תיקיית המקור המעודכנת לקובץ פלאגין אחד (`.plugin`), **מתקין אותו במקום הגרסה הישנה, ומוחק את הישנה** - כך שנשארת רק גרסה אחת, מעודכנת. אין כפילות, ואין מה למחוק ידנית.

> התהליך במשפט: **מתקנים את תיקיית המקור ← עושים rebuild ← הפלאגין נארז, מותקן, והישן מוחלף ← פותחים שיחה חדשה.**

## מה חדש (חשוב)

בגרסה קודמת ה-rebuild רק **אָרַז** קובץ, והמשתמש היה צריך לגרור ולהתקין ידנית - ולא תמיד היה ברור אם הגרסה הישנה הוחלפה או נשארה. **מעכשיו ה-rebuild גם מתקין ומחליף לבד:** הוא שם את החדשה במקום הישנה ומוחק את הישנה. אין "גרסה ישנה תקועה", אין כפילות, ואין מה למחוק בעצמכם.

בנוסף, נוספו **ארבע בדיקות מבנה חובה לפני האריזה** (שלב 2 למטה). הן נולדו מתקלות אמיתיות שכולן נכשלות בשקט, בלי שום הודעת שגיאה - סוכן שנראה מותקן אבל לא מופיע, או פלאגין שלא נטען בכלל.

## מתי מפעילים

אחרי כל שינוי בסוכן. "שמרתי" זה לא "הסוכן המותקן יודע" - רק אחרי rebuild.

## מערכת הפעלה - קרא לפני שאתה מריץ פקודה

הפקודות למטה שונות בין Mac, Windows ו-Linux. **בדוק את מערכת ההפעלה של המשתמש** - היא רשומה ב-`CLAUDE.md` של הריפו, בשדה "מע' הפעלה" (אם לא בטוח - שאל את המשתמש) - **ובחר את הפקודה המתאימה.** לעולם אל תריץ פקודת Mac קשיחה כשהמשתמש על Windows, ולהפך.

## השלבים שאני מבצע

1. **מזהה את הסוכן/ים לארוז.** מחפש תיקיות סוכן ב-`agents/ready/` וב-`agents/in-progress/` (כל תת-תיקייה שיש בה `.claude-plugin/plugin.json` - גם בעומק, למשל `agents/ready/<שם-הסוכן>/plugin/.claude-plugin/plugin.json`). אם יש כמה - שואל את המשתמש איזה. אם יש אחד - ממשיך איתו ומודיע איזה. **אם המשתמש ביקש "את כל הסוכנים" / "לעדכן את כולם" - חוזר על כל התהליך (שלבים 2-7) לכל תיקיית סוכן בנפרד, ומדווח בסוף רשימה של מה נבנה והותקן.**

2. **מוודא מקור תקין - שלוש בדיקות חובה, בסדר הזה. כל אחת שנכשלת - עוצרים ומתקנים במקור לפני שממשיכים לארוז:**
   - **א. זיהוי שורש הפלאגין.** שורש הפלאגין הוא התיקייה שמכילה את `.claude-plugin/plugin.json` - וזו לא תמיד תיקיית הסוכן עצמה (למשל `agents/ready/<שם-הסוכן>/plugin/`). **אורזים את שורש הפלאגין, לא את תיקיית הסוכן.** אם אין `plugin.json` בכלל - עוצר ומסביר, בלי לנחש.
   - **ב. plugin.json בלי BOM ו-JSON תקין.** בודק את 3 הבייטים הראשונים של הקובץ: אם הם `EF BB BF` (UTF-8 BOM) - **הפלאגין כולו לא ייטען ב-Claude, בשקט, בלי שגיאה.** במקרה כזה כותבים את הקובץ מחדש ב-UTF-8 בלי BOM (למשל ב-PowerShell: לקרוא עם `Get-Content -Raw`, לכתוב עם `[System.IO.File]::WriteAllText($path, $content)` שכותב UTF-8 בלי BOM). אחר כך מוודאים שה-JSON נפרס תקין (`node -e "JSON.parse(...)"` או `ConvertFrom-Json`). בדיקת BOM ב-PowerShell: `[System.IO.File]::ReadAllBytes($path)[0..2]` - אם זה 239,187,191 יש BOM.
   - **ג. SKILL.md במקום הנכון.** אם הפלאגין כולל skill - קובץ `SKILL.md` חייב לשבת ב-`skills/<שם-הסקיל>/SKILL.md` בתוך שורש הפלאגין. **`SKILL.md` בשורש הפלאגין לא מזוהה בכלל - הסוכן יותקן אבל לא יופיע ברשימת ה-skills.** אם נמצא `SKILL.md` בשורש: מעבירים אותו ל-`skills/<שם>/SKILL.md`, מעבירים את מסמכי הידע שלו ל-`skills/<שם>/references/` (למשל `master-library/` בשורש ← `skills/<שם>/references/master-library/`), ומוודאים שהנתיבים שמוזכרים בתוך גוף ה-SKILL.md (כמו `references/master-library/...`) תואמים למבנה החדש. התיקון נעשה **בתיקיית המקור** - כך שהוא נשמר לכל rebuild עתידי.
   - **ד. סכמת `plugin.json` תקינה - לא רק JSON תקין.** גם כשה-JSON נפרס בהצלחה, הפלאגין לא ייטען אם הסכמה שבורה - למשל `author` שהוא מחרוזת במקום אובייקט (הצורה הנכונה: `"author": {"name": "..."}`), או שדות חובה חסרים. `ConvertFrom-Json` / `JSON.parse` עוברים על זה בשקט (JSON תקין, סכמה לא), אז הבדיקה חייבת להיות מפורשת: ודא ש-`author` הוא אובייקט, ושקיימים `name` ו-`version`. אם לא - תקן בתיקיית המקור.

3. **מעלה את מספר הגרסה** ב-`plugin.json` (הספרה האחרונה ב-`version`, למשל מ-`0.1.0` ל-`0.1.1`). זה מה שמסמן שזו גרסה חדשה.

4. **מוודא שקיימת `plugins-to-install/`** בשורש ריפו הקורס - התיקייה שמכילה את `agents/` (אותה תיקייה שהשיחה מחוברת אליה). אם לא קיימת - **יוצר אותה שם בעצמו** (זה צפוי אצל מי שסיים את ההכנה לפני שהתיקייה נכנסה למבנה - יוצרים וממשיכים). לא שם אותה מחוץ לריפו.

5. **אורז** את **שורש הפלאגין** (כפי שזוהה בשלב 2א - לא בהכרח תיקיית הסוכן עצמה) לקובץ `.plugin` בתוך `plugins-to-install/`. פקודת האריזה לפי מערכת ההפעלה:
   - **Mac / Linux:**
     ```bash
     cd <שורש-הפלאגין>
     zip -r <שורש-הריפו>/plugins-to-install/<שם-הסוכן>.plugin . -x "*.DS_Store" -x "*/.git/*"
     ```
   - **Windows (PowerShell) - אסור `Compress-Archive`:** ב-Windows PowerShell 5.1, `Compress-Archive` כותב path separators עם backslash בתוך ה-zip (לא forward slash) - זה שובר קוראי zip חוצי-פלטפורמה (כולל מתקין הפלאגינים), וגורם ל-"plugin.json is not valid JSON" גם כשה-JSON תקין, כי הוא לא נמצא בנתיב הצפוי. חובה לבנות את ה-zip ישירות דרך `System.IO.Compression.ZipArchive` עם שמות entry בעלי forward slash:
     ```powershell
     Add-Type -AssemblyName System.IO.Compression
     Add-Type -AssemblyName System.IO.Compression.FileSystem
     $src = (Resolve-Path "<שורש-הפלאגין>").Path.TrimEnd('\')
     $dest = "<שורש-הריפו>\plugins-to-install\<שם-הסוכן>.plugin"
     if (Test-Path $dest) { Remove-Item $dest -Force }
     $zip = [System.IO.Compression.ZipFile]::Open($dest, [System.IO.Compression.ZipArchiveMode]::Create)
     Get-ChildItem -Path $src -Recurse -File | ForEach-Object {
         $entryName = ($_.FullName.Substring($src.Length).TrimStart('\','/')) -replace '\\','/'
         $entry = $zip.CreateEntry($entryName, [System.IO.Compression.CompressionLevel]::Optimal)
         $s = $entry.Open(); $fs = [System.IO.File]::OpenRead($_.FullName)
         try { $fs.CopyTo($s) } finally { $fs.Close(); $s.Close() }
     }
     $zip.Dispose()
     ```
   - העיקר: קובץ אחד בשם `<שם-הסוכן>.plugin` שמכיל את תוכן שורש הפלאגין, כולל `.claude-plugin/`, עם forward slash בכל נתיבי ה-entries. אם `zip` לא זמין ב-Mac/Linux - השתמש בכלי הארכוב של המערכת, אבל ודא forward slash.

6. **מתקין ורושם את הגרסה החדשה** (החלק שמייתר מחיקה ידנית). תיקיית הפלאגינים המותקנים:
   `~/.claude/plugins/marketplaces/local-desktop-app-uploads/<שם-הסוכן>`
   - אם התיקייה `~/.claude/plugins/marketplaces/local-desktop-app-uploads` **לא קיימת** (סביבה שאינה Claude Desktop מקומי) - **מדלג על ההתקנה האוטומטית**, ומנחה התקנה ידנית (ראה למטה). לא מנחש נתיבים.
   - אם היא קיימת:
     - **א. מחלץ ומעתיק את הקבצים.** מחלץ את ה-`.plugin` לתיקייה זמנית. פקודת החילוץ לפי מערכת ההפעלה: Mac - `ditto -xk` או `unzip`; Windows - `Expand-Archive`; Linux - `unzip`. מוודא שבתיקייה שחולצה יש `.claude-plugin/plugin.json`. **ב-Windows: לחלץ לנתיב זמני קצר (למשל `C:\Temp\<שם-הסוכן>`), לא לתת-תיקייה עמוקה - MAX_PATH הוא 260 תווים, ומשתמש עם OneDrive + תיקיות בעברית חוצה אותו ו-`ExtractToDirectory` נכשל בשקט.** **פלאגין כבד (למשל עם `node_modules`, אלפי קבצים): `Expand-Archive` ב-Windows איטי מאוד ועלול להיתקע - במקרה כזה מדלגים על החילוץ ומעתיקים ישירות משורש הפלאגין במקור עם `robocopy <מקור> <יעד> /E` (exit code 0 או 1 = הצלחה).**
     - **ב.** אם כבר קיימת תיקייה מותקנת בשם הזה - **מגבה אותה קודם** (שינוי שם ל-`<שם-הסוכן>.bak`), ורק אז מעתיק את החדשה למקומה. כך הישן מוחלף בצורה בטוחה.
     - **ג. רושם את הפלאגין - שלושה קבצי רישום.** זה מה שגורם לפלאגין להיטען. קבצים על הדיסק לבד לא מספיקים - בלי שלושת הקבצים האלה הפלאגין ייראה מותקן לחלוטין ופשוט לא יעלה, בלי שום שגיאה. בכל קובץ: **קורא קודם, שומר על כל שאר הרשומות, כותב מחדש UTF-8 בלי BOM** (ב-Windows: `[System.IO.File]::WriteAllText`).
       1. **`~/.claude/plugins/installed_plugins.json`** (סכמה `"version": 2`): הרשומות יושבות **בתוך** המפתח `plugins` (לא ברמה העליונה של הקובץ!), כל אחת כמפה `"<שם-הסוכן>@local-desktop-app-uploads"` ← **מערך בן איבר אחד**: `{"scope": "user", "installPath": "<נתיב מלא לתיקייה המותקנת>", "version": "<גרסה>", "installedAt": "<ISO>", "lastUpdated": "<ISO>"}`. קיים - עדכן `version` ו-`lastUpdated`; לא קיים - הוסף רשומה מלאה.
       2. **`~/.claude/plugins/marketplaces/local-desktop-app-uploads/.claude-plugin/marketplace.json`**: יש מערך `plugins`, כל איבר `{"name": "<שם-הסוכן>", "version": "<גרסה>", "source": "./<שם-הסוכן>"}`. `<שם-הסוכן>` כבר במערך - עדכן `version`; לא - הוסף איבר. **בלי זה הפלאגין לא מופיע ברשימה.**
       3. **`~/.claude/settings.json`**, מפתח `enabledPlugins` (אובייקט): הוסף/ודא `"<שם-הסוכן>@local-desktop-app-uploads": true`. **בלי זה הוא נשאר disabled ולא עולה.**
     - **ד. אימות - כל 4 המישורים, לפני מחיקת הגיבוי.** פלאגין עולה רק אם ארבעתם מיושרים, אז בודקים את כולם: (1) הקבצים בתיקייה המותקנת - `.claude-plugin/plugin.json` בלי BOM, ואם למקור יש skill גם `skills/<שם>/SKILL.md` (לא בשורש); (2) `<שם-הסוכן>` קיים במערך `plugins` של `marketplace.json`; (3) המפתח `<שם-הסוכן>@local-desktop-app-uploads` קיים ב-`installed_plugins.json` עם הגרסה החדשה; (4) `enabledPlugins["<שם-הסוכן>@local-desktop-app-uploads"] == true` ב-`settings.json`. **רק אחרי ש-4 עברו** - מוחק את הגיבוי (`.bak`) ואת התיקייה הזמנית. אם אחד נכשל - משחזר מהגיבוי ומנחה התקנה ידנית.

7. **מדווח למשתמש:** מה נעשה (נארז / הותקן / הישן הוחלף), הגרסה החדשה, ושצריך לפתוח שיחה חדשה כדי שהשינוי ייכנס לתוקף.

## מה המשתמש עושה אחרי (אני מנחה אותו)

**אם ההתקנה האוטומטית הצליחה:**
> "הסוכן נבנה, הותקן, והגרסה הישנה הוחלפה - נשארה רק גרסה אחת מעודכנת (v<גרסה>). אין מה למחוק. עכשיו:
> 1. סגרו את קלוד לגמרי ופתחו מחדש (הסשן הנוכחי עדיין טעון עם הגרסה הקודמת).
> 2. פתחו שיחה חדשה עם הסוכן ובדקו שהוא מכיר את השינוי."

**אם ההתקנה האוטומטית דולגה (סביבה לא נתמכת):**
> "הפלאגין המעודכן מחכה ב-`plugins-to-install/<שם>.plugin`. עכשיו:
> 1. התקינו אותו מחדש בקלוד (גרירה לחלון, או הגדרות ← פלאגינים ← התקנה מקובץ). **ההתקנה מחליפה את הגרסה הישנה - לא נוצרת כפילות, אין מה למחוק.**
> 2. סגרו את קלוד לגמרי ופתחו מחדש.
> 3. פתחו שיחה חדשה ובדקו שהסוכן מכיר את השינוי."

## כללים

- **מקור אחד.** מתקנים תמיד בתיקיית המקור (`agents/ready/<שם>/` או `agents/in-progress/<שם>/`), לעולם לא בגרסה המותקנת. שינוי בקוד - תמיד במקור.
- **לא נוגע בקבצי המקור.** הסקיל אורז מהמקור ומעתיק - הוא לא משנה ולא מוחק את תיקיית המקור. חריג אחד: תיקוני המבנה של שלב 2 (BOM, מיקום SKILL.md) נעשים במקור בכוונה - כדי שהתיקון יחזיק לכל rebuild עתידי. את הגרסה ה**מותקנת** כן מחליף - זו כל המטרה.
- **פקודות מותאמות למערכת ההפעלה.** לפני כל פקודה - בדוק Mac / Windows / Linux (שדה "מע' הפעלה" ב-`CLAUDE.md`) ובחר בהתאם. לא פקודות Mac קשיחות.
- **גיבוי לפני החלפה.** תמיד לגבות את המותקן הישן (`.bak`) לפני העתקת החדש, כדי שאפשר לשחזר אם ההעתקה נכשלת.
- **לא ממציא נתיבים.** אם לא מצאתי תיקיית סוכן / `plugin.json` / תיקיית מותקנים - עוצר ושואל את המשתמש, לא מנחש.
- שפה למשתמש: עברית פשוטה. נתיבים ושמות קבצים: אנגלית.
